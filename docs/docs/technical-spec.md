# Техническое задание

## Назначение

`goals-front` предоставляет пользовательский интерфейс системы целей и наград. Приложение позволяет
планировать цель через последовательность шагов, отслеживать её состояние и завершать жизненный цикл
цели.

## Реализованный объём

- вход в приложение через Google OAuth;
- просмотр собственных целей по статусам;
- создание цели и её шагов;
- просмотр, активация и удаление новой цели;
- отмена и завершение активной цели;
- завершение доступного шага;
- просмотр пользователей и количества их активных и завершённых целей;
- светлая и тёмная темы.

## Экраны

| Экран         | Маршрут            | Назначение                                   |
| ------------- | ------------------ | -------------------------------------------- |
| Вход          | `/login`           | Вход в приложение                            |
| Цели          | `/app`             | Просмотр и управление собственными целями    |
| Создание цели | `/app/create-goal` | Создание цели и последовательности шагов     |
| Пользователи  | `/users`           | Просмотр пользователей и статистики их целей |

## Основные сценарии

### Создание и запуск цели

1. Пользователь открывает форму создания.
2. Заполняет название, описание и дедлайн цели.
3. Добавляет и заполняет шаги.
4. Сохраняет цель в статусе `created`.
5. На основном экране раскрывает группу «Новые».
6. Запускает цель либо удаляет её вместе со связанными шагами.

### Выполнение цели

1. Активированная цель отображается в группе «Выполняются».
2. Пользователь видит сроки и состояние шагов.
3. Доступный шаг можно завершить с результатом.
4. Цель можно отменить либо завершить с пожеланием к награде.

### Просмотр пользователей

1. Пользователь открывает раздел «Пользователи».
2. Для каждой карточки видит количество выполняемых и завершённых целей.
3. Переход к целям выбранного пользователя пока не выполняется.

## Ограничения текущей реализации

- отдельный экран целей выбранного пользователя отсутствует;
- ошибки чтения данных не имеют самостоятельного визуального состояния;
- удаление, отмена и активация выполняются без подтверждения;
- автоматические unit- и e2e-тесты пока не настроены.

Подробное поведение каждого состояния находится в разделе [«Документация»](./documentation.md).
