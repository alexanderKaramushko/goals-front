# Новая цель: просмотр, активация и удаление

## Назначение

Состояние основного экрана целей, в котором пользователь раскрывает группу «Новые», просматривает
ещё не запущенную цель и может активировать или удалить её.

## Маршрут

`/app`

Это не отдельный маршрут: состояние отображается внутри страницы целей, когда получена хотя бы одна
цель со статусом `created` и раскрыт соответствующий аккордеон.

## Доступ

Только для аутентифицированного пользователя. Цели загружаются для `subjectId` текущего профиля.

## Просмотр новой цели

После загрузки целей frontend группирует записи со статусом `created` в аккордеон «Новые». В карточке
видны дедлайн, описание и шаги. Отдельной страницы деталей или редактирования цели нет; просмотр
выполняется непосредственно в карточке.

## Активация

Пользователь нажимает зелёную иконку запуска с tooltip и `aria-label` «Начать выполнение».

Backend разрешает активацию, только если:

- цель принадлежит текущему пользователю и находится в статусе `created`;
- дедлайн цели не находится в прошлом по `x-user-timezone`;
- среди шагов нет шагов с дедлайном в прошлом.

При успехе цель переходит в статус `active`, после чего frontend повторно запрашивает список целей.
Она исчезает из группы «Новые» и появляется в группе «Выполняются». Ответы `400` и другие ошибки
показываются через snackbar.

## Удаление

Пользователь нажимает красную иконку корзины с tooltip и `aria-label` «Удалить цель». Подтверждение
перед удалением не показывается.

Backend удаляет только цель в статусе `created`, принадлежащую текущему пользователю. Связанные шаги
удаляются вместе с целью в одной транзакции. После успешного ответа frontend повторно получает список
целей. Для цели в другом статусе backend возвращает `400`, для отсутствующей цели — `404`.

## Используемые API

| Назначение        | Метод и endpoint                          | Результат                          |
| ----------------- | ----------------------------------------- | ---------------------------------- |
| Цели пользователя | `GET /api/v1/targets/get-all/:userId`     | Возвращает цель в группе `created` |
| Шаги цели         | `GET /api/v1/steps/get-all/:targetId`     | Заполняет прогресс шагов           |
| Удаление          | `DELETE /api/v1/targets/delete/:targetId` | Удаляет цель и связанные шаги      |
| Активация         | `PUT /api/v1/targets/activate/:targetId`  | Переводит цель в `active`          |

Все запросы goals-service получают заголовок `x-user-timezone` от общего axios-клиента.

## Состояния и ошибки

- во время загрузки шагов карточка показывает skeleton-прогресс;
- специального подтверждения удаления или активации нет;
- ошибки мутаций показываются snackbar с сообщением backend либо общей ошибкой;
- ошибки чтения целей и шагов отдельно не отображаются;
- после действия список перезапрашивается целиком;
- одновременные повторные клики явно не блокируются состоянием loading в кнопках.
