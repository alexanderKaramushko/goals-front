# Цели

## Назначение

Основной экран пользователя: показывает цели, сгруппированные по статусу, прогресс шагов и доступные
операции над целью.

## Маршрут

`/app`

Параметры пути и query-параметры не используются.

## Доступ

Только для аутентифицированного пользователя. При `401` запроса профиля общая верхняя панель
перенаправляет на `/login`. Отдельного route guard нет.

## Состояния страницы

### Загрузка целей

До завершения запроса целей отображаются четыре прямоугольных skeleton-блока. Заголовок и кнопка
создания остаются доступными.

### Загрузка шагов

После получения целей каждый `StepProgress` независимо загружает шаги и временно показывает четыре
skeleton-шага.

### Данные загружены

Цели группируются в аккордеоны: «Выполняются» (`active`), «Новые» (`created`), «Завершенные»
(`completed`) и «Отмененные» (`cancelled`). Пустые группы не отображаются.

### Пустое состояние

Специального текста или иллюстрации нет: если массив целей пуст, область под заголовком остаётся
пустой.

### Ошибка

Хук получения целей и шагов не передаёт ошибку в UI. После ошибки данные выглядят как пустые
массивы, поэтому пользователь не отличает ошибку от отсутствия целей или шагов.

### Нет доступа

Реализован только редирект на `/login` при `401` запроса профиля. Ответы `403` отдельно не
обрабатываются.

## Действия пользователя

| Действие          | Условие                                                   | Результат                                                                               |
| ----------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Создать цель      | Всегда                                                    | Переход на `/app/create-goal`                                                           |
| Раскрыть группу   | В группе есть цели                                        | Показываются или скрываются карточки                                                    |
| Удалить цель      | Статус `created`                                          | `DELETE`, затем повторное получение целей                                               |
| Активировать цель | Статус `created`, backend принимает дедлайны цели и шагов | Статус становится `active`, список обновляется                                          |
| Отменить цель     | Статус `active`                                           | Статус становится `cancelled`, список обновляется                                       |
| Завершить цель    | Статус `active`                                           | Для непросроченной цели открывается ввод комментария; для просроченной отправляется `-` |
| Завершить шаг     | Это первый незавершённый непросроченный шаг активной цели | Открывается ввод результата, после сохранения шаги обновляются                          |

### Подписи иконок действий

| Статус цели             | Иконка                              | Tooltip и `aria-label`     | Результат                                        |
| ----------------------- | ----------------------------------- | -------------------------- | ------------------------------------------------ |
| `created`               | Красная корзина                     | «Удалить цель»             | Без подтверждения удаляет цель и её шаги         |
| `created`               | Зелёная кнопка запуска              | «Начать выполнение»        | Активирует цель после backend-проверок дедлайнов |
| `active`                | Коричневый крест                    | «Отменить цель»            | Без подтверждения переводит цель в `cancelled`   |
| `active`, просрочена    | Зелёная галочка                     | «Завершить»                | Сразу отправляет завершение с комментарием `-`   |
| `active`, не просрочена | Зелёная иконка сообщения с галочкой | «Завершить с комментарием» | Открывает поле пожеланий к награде               |

## Используемые API

| Назначение            | Метод и endpoint                          | Когда вызывается                                           |
| --------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| Профиль и `subjectId` | `GET /auth/users/profile`                 | При открытии страницы через верхнюю панель и саму страницу |
| Цели пользователя     | `GET /api/v1/targets/get-all/:userId`     | После получения `subjectId`                                |
| Шаги цели             | `GET /api/v1/steps/get-all/:targetId`     | Для каждой карточки цели                                   |
| Удаление цели         | `DELETE /api/v1/targets/delete/:targetId` | По кнопке удаления цели в `created`                        |
| Активация цели        | `PUT /api/v1/targets/activate/:targetId`  | По кнопке запуска цели в `created`                         |
| Отмена цели           | `POST /api/v1/targets/cancel/:targetId`   | По кнопке отмены активной цели                             |
| Завершение цели       | `PUT /api/v1/targets/complete/:targetId`  | После подтверждения завершения                             |
| Завершение шага       | `PUT /api/v1/steps/complete/:stepId`      | После ввода результата шага                                |

К запросам goals-service axios-клиент добавляет заголовок `x-user-timezone`.

## Используемые общие компоненты

- [`Background`](../ui/common-elements.md#background) — фон страницы;
- [`Switch`](../ui/common-elements.md#switch) — смена темы;
- [`Stepper`](../ui/common-elements.md#stepper) — прогресс шагов;
- [`Popper`](../ui/common-elements.md#popper) — форма завершения цели или шага.

## Особенности и ограничения

- frontend вычисляет подписи дедлайнов повторно по локальному времени, хотя backend также возвращает
  `isOutdated`;
- завершить можно только следующий по сроку шаг, и только пока он не просрочен;
- кнопки удаления, отмены и активации не требуют дополнительного подтверждения;
- API-ошибки мутаций показываются snackbar, ошибки чтения не показываются;
- разные аккордеоны используют повторяющиеся значения `id`/`aria-controls` для нескольких групп;
- состояние завершения просроченной цели в frontend расходится с бизнес-правилом backend, которое
  запрещает завершать цель после дедлайна.
